## Outcome

UX-1A makes the first shared presentation paths safe and gives five target
surfaces one explicit state vocabulary. It does not redesign the app shell,
reorder Today Decision, change the global theme, or migrate any additional data
source.

The batch is complete only when:

1. dynamic chip labels cannot inject markup or CSS;
2. target UI, session state, and newly saved chat/UI-owned history records do not
   contain raw diagnostics;
3. legacy AI Chat failure records receive a read-time safe projection without
   rewriting the files;
4. source, content, freshness, and operation states remain independently visible;
5. target artifact failures remain fail-soft;
6. routes, handoffs, provider calls, candidate order, API behavior, and global
   theme remain unchanged.

#### Resolution R1A-01 — UX-0 remains historical

`docs/ui-ux/quant-radar-ui-v2-baseline.json` is immutable pre-redesign evidence.
It MUST NOT be regenerated or updated to match UX-1A.

`cec8135ca49aba1859c96635865de72f88993f6aa838fca72da3301a5aff6930`

- `pages`
- `navigation`
- `same_session_routes`
- `handoffs`
- `source_roots`

Safety fields (`unsafe_html` and `diagnostics`) move forward through a separate,
versioned UX-1A classification/current contract. This records intentional
removals without falsifying the historical baseline.

#### Resolution R1A-02 — persisted means the target UI boundary

UX-1A applies the no-raw-diagnostic rule to:

- rendered target UI;
- target session-state values owned by AI Chat and candidate controls;
- every new AI Chat record;
- every new history row written by `ui/_candidate_controls.py`;
- legacy AI Chat system-failure messages when read for display.

UX-1A does not rewrite, delete, or quarantine existing chat, status, analytics,
or pipeline files. The chat store recognizes only the exact legacy assistant
failure format previously generated by `ui/ai_chat.py` and returns a stable safe
message at read time. Normal user/assistant content remains byte-for-byte content
equivalent after normalization. Existing operational status files remain inputs,
but their raw message/path/log fields are no longer rendered or copied by the
target UI.

Pipeline-wide at-rest remediation in `scripts/run_status.py`,
`scripts/run_candidate_pipeline.py`, `scripts/02_llm_score.py`,
`scripts/03_rank_candidates.py`, and `scripts/claude_auth_flow.py` is explicitly
deferred. UX-1A MUST NOT claim that all repository diagnostic candidates or all
historical files are clean.

#### Resolution R1A-03 — Today includes its direct helper

`ui/today_decision.py::render()` calls `ui/_candidate_controls.py::render()`.
Therefore `_candidate_controls.py` is in the production scope. PID, absolute
paths, command/launcher arrays, log tails, auth payload messages, and arbitrary
status error/message fields are removed from presentation and from the UI-owned
session projection. Buttons, parameters, progress, status labels, auth/resume
flow, and history metrics remain.

#### Resolution R1A-04 — reflection detail is not a diagnostic console

Schedules keeps the human-readable, allowlisted reflection summary. The raw LLM
JSON tab, full Markdown-source tab, and raw-source download are removed from this
target surface because they can expose arbitrary payload diagnostics. Suspicious
diagnostic content inside the retained structured summary is replaced as a whole
with stable copy and event code; it is never partially echoed.

#### Resolution R1A-05 — fail-soft includes wrong shape and unreadable reads

`_shared.load_json()` already returns `None` for missing, half-written,
malformed, and unreadable JSON. UX-1A preserves that contract and closes target
callers that assume a dict/list root. `_shared.load_ledger()` and report-directory
enumeration gain the equivalent read boundary. Schedule result fetchers receive
a class-only logged exception boundary so a single corrupt artifact cannot crash
the page.

## Design Contract

### `ui/_design.py`

This module is pure Python and MUST NOT import Streamlit.

It defines immutable maps for:

- `surface.canvas`, `surface.panel`, `surface.elevated`;
- `text.primary`, `text.secondary`, `text.disabled`;
- `border.default`, `border.focus`;
- `interactive.primary`, `interactive.hover`, `interactive.disabled`;
- `feedback.info`, `feedback.success`, `feedback.warning`, `feedback.error`;
- `signal.bullish`, `signal.neutral`, `signal.bearish`, `signal.avoid`.

Component-specific chip colors must reach 4.5:1 for normal-sized chip text
against both actual composited chip backgrounds (the approved chip fill alpha
over the current canvas and panel), not merely against the unblended surfaces.
Existing public `_shared` color constants remain available for charts and
callers. `resolve_chip_color(value)` accepts semantic
token names and the current fixed color constants, maps them to an approved chip
color, and returns the muted chip token for every unknown, malformed, or malicious
value. It never raises and never returns the caller's untrusted string.

The module also provides pure contrast calculation used by tests. It does not
write CSS or update `.streamlit/config.toml`.

### `ui/_components.py`

The minimum state object is immutable and validated:

```python
DataState(
    source="authoritative | fallback | unavailable",
    content="populated | empty | partial | unknown",
    freshness="fresh | stale | unknown",
    operation="idle | loading | success | failure",
    source_id="allowlisted source identifier",
    reason_code=None,
    event_code=None,
    as_of=None,
    recovery_key=None,
)
```

Rules:

- `reason_code` accepts only the existing artifact-unavailable/client-failure
  codes plus explicitly declared UI-safe reason codes;
- `event_code` must match `QR-[A-Z0-9-]+-[0-9]{3}` and must also belong to the
  fixed event-code registry; matching the syntax alone is insufficient;
- `source_id` and `recovery_key` are allowlisted identifiers mapped to fixed
  Traditional Chinese copy;
- no renderer accepts `Exception`, arbitrary `details`, response bodies, paths,
  URLs, commands, or free-form source labels;
- `as_of` accepts only `datetime.date`, `datetime.datetime`, or `None`; pages
  convert already-validated ISO dates before construction, so arbitrary strings
  cannot become metadata;
- the renderers use native `st.info`, `st.warning`, `st.error`, `st.success`, and
  `st.caption`; they do not add `unsafe_allow_html=True`.

Only these public renderers are introduced:

- `render_state_banner(state)`
- `render_source_meta(state)`

### State Precedence and Composition

The renderer generates one fixed message containing every applicable dimension;
it does not collapse the object to a flat enum.

Severity order is:

1. operation failure;
2. source unavailable;
3. source fallback;
4. partial content;
5. stale freshness;
6. empty content;
7. loading;
8. success;
9. normal informational metadata.

Precedence chooses the visual container only. It MUST NOT remove lower-priority
facts from the generated text. In particular:

- `source=unavailable` always says the authoritative source is unavailable;
- `source=fallback` always says fallback is in use;
- empty/partial/stale/unknown remain visible alongside source and operation;
- an authoritative-unavailable state can never be relabeled fallback because
  local data exists;
- `freshness=unknown` is honest metadata, not a warning invented from age;
- stale is allowed only when the existing domain already supplies that state.

Valid-state constraints are explicit:

- an unavailable source cannot claim populated/partial content or fresh/stale
  data;
- fresh/stale requires a real `as_of` and an available authoritative/fallback
  source;
- `as_of` may accompany `freshness=unknown` without implying age quality;
- operation remains orthogonal and may combine with every otherwise valid data
  composition.

### Stable Event Codes

| Event code | Surface |
| --- | --- |
| `QR-CHAT-LOAD-001` | Saved chat load failure |
| `QR-CHAT-DELETE-001` | Saved chat delete failure |
| `QR-CHAT-SAVE-001` | Saved chat write failure |
| `QR-CHAT-CONTEXT-001` | Context attachment failure |
| `QR-CHAT-ANSWER-001` | Assistant/provider failure and legacy safe projection |
| `QR-TODAY-TRADE-STATE-001` | Today trade-state computation failure |
| `QR-TODAY-ARTIFACT-001` | Today malformed/unreadable target artifact |
| `QR-CANDIDATE-LAUNCH-001` | Candidate launch/resume failure |
| `QR-CANDIDATE-AUTH-001` | Claude auth operation failure |
| `QR-CANDIDATE-STATUS-001` | Candidate status payload reports failure |
| `QR-SCHEDULES-RESULT-001` | Schedule result fetcher failure |
| `QR-SCHEDULES-REFLECTION-001` | Reflection field suppressed for diagnostic content |

Internal logging format is fixed and class-only:

`event_code=<stable code> error_type=<ExceptionClass>`

No log statement interpolates `str(exc)`, `repr(exc)`, exception args, payload,
path, URL, port, profile, command, auth message, or response body.

### Exact Adapter Mapping

`operation` describes a user-triggered action, not whether a page needed a
fallback read. Therefore a transport/client failure that successfully resolves
to fallback data remains `operation=idle`; degradation is carried by
`source=fallback` and its stable reason.

Registry/feed adapters use this exact mapping:

| Existing status | Source | Content | Freshness | Operation | Notes |
| --- | --- | --- | --- | --- | --- |
| `api_available` with rows | `authoritative` | `populated` | `unknown` | `idle` | AI Updates may also supply its validated latest date as `as_of` |
| `api_available` without rows | `authoritative` | `empty` | `unknown` | `idle` | No fallback |
| `api_unavailable` | `unavailable` | `unknown` | `unknown` | `idle` | Existing server reason; zero local read |
| `local_fallback` with rows | `fallback` | `populated` | `unknown` | `idle` | Existing client reason remains visible |
| `local_fallback` without rows | `fallback` | `empty` | `unknown` | `idle` | Fallback and empty both visible |
| `all_unavailable` | `unavailable` | `unknown` | `unknown` | `idle` | Existing client reason; no trusted content |

Non-feed adapters use this exact policy:

| Surface/event | Source | Content | Freshness | Operation |
| --- | --- | --- | --- | --- |
| Today trade-state populated | `authoritative` | `populated` | `unknown` | `idle` |
| Today trade-state empty | `authoritative` | `empty` | `unknown` | `idle` |
| Today trade-state read/computation failure | `unavailable` | `unknown` | `unknown` | `idle` |
| Schedule result present/missing | `authoritative` | `populated` / `empty` | `unknown` | `idle` |
| Schedule result fetch/safety suppression | `unavailable` | `unknown` | `unknown` | `idle` |
| Chat normal session | `authoritative` | current `populated` / `empty` | `unknown` | `idle` |
| Chat load/delete/save/context failure | `authoritative` | current `populated` / `empty` | `unknown` | `failure` |
| Chat answer/provider failure | `unavailable` | `unknown` | `unknown` | `failure` |
| Candidate launch/resume failure | `authoritative` | `unknown` | `unknown` | `failure` |
| Candidate auth waiting/success/failure | `authoritative` | `unknown` | `unknown` | `loading` / `success` / `failure` |
| Candidate persisted run active/succeeded/failed | `authoritative` | `populated` | `unknown` | `loading` / `success` / `failure` |

An operation-only banner renders the operation and event/recovery copy; it does
not pretend a client action failure changed the current chat/candidate data
source. Source metadata is rendered for feed/result states, not redundantly for
every transient chat button failure.

## Target Adoption Mapping

### Today Decision

- Do not change `render()` order.
- Replace only trade-state failure/empty state with `DataState` rendering.
- Keep populated metrics and same switch-page action.
- Make every JSON root assumption explicit before `.get()`/iteration.
- Treat invalid roots as empty/unavailable safe states, not exceptions.
- Keep candidate IDs, ordering, provider calls, and handoffs exact.

### Candidate Controls

- Keep all controls, parameter bounds/defaults, launch modes, progress metrics,
  auth/resume behavior, and history table columns.
- Store only `mode`, fixed `mode_label`, and safe operation/event state in
  `candidate_pipeline_last_launch`; do not store PID, command, launcher,
  unit/profile, absolute path, log path, pending path, auth payload, or raw message.
- At render entry, replace pre-upgrade raw launch metadata already present in the
  live session with that safe projection.
- Do not read or display log tails.
- Display only allowlisted stage label, status label, percent, and numeric metrics.
- Display the recognized LLM progress pattern only; discard arbitrary stage text.
- Convert raw `errors[].message` to the stable status event.
- Replace fixed backend vocabulary (`CLI`, environment-variable/token/profile
  names, container paths, login output/URL instructions) with stable user-language
  auth status and recovery copy.
- New history rows written here keep operational counts/IDs but replace raw
  warnings/errors and path-bearing output details with stable/count projections.
- Existing operational history remains readable for the existing table, which
  already selects fixed metric fields.

### AI Chat and Store

- Keep every existing session key, open/close flow, mode, save toggle, context
  workflow, and confirmation behavior.
- Load/delete/save/context failures render shared stable banners and class-only
  logs. A save failure keeps the current in-memory messages and never recursively
  attempts to persist its own error banner.
- Assistant failure appends only fixed safe copy plus
  `QR-CHAT-ANSWER-001`; `_render_messages` recognizes that fixed message and uses
  the shared banner.
- `_save_if_needed()` may persist the safe message, never the exception.
- Store read-time projection recognizes only the exact historical generated
  assistant prefix/body shape. It does not rewrite files and does not broadly
  redact user or normal assistant content.
- `_init_state()` and `_load_payload()` apply that same narrow projection so a
  legacy failure already present in a live session cannot remain raw after the
  upgraded code reruns.
- Static AI Chat CSS remains classified static; UX-2 focus/modal redesign is not
  pulled into this batch.

### AI Updates

- Map API available/unavailable/local fallback/all unavailable and content
  empty/populated to `DataState`.
- Derive `as_of` only from the latest validated update date; freshness remains
  `unknown` because no stale rule exists.
- Replace the unsafe date HTML with native text/caption layout.
- Keep ordering, filter threshold, tags, summaries, and link buttons exact.

### Schedules

- Map registry source/content state without changing authoritative unavailable
  or fallback rules.
- Freshness remains `unknown`; registry metadata supplies no time.
- Render name/category/status through native text and escaped shared chips; no
  dynamic heading HTML.
- Wrap each local result fetcher with stable event/class-only logging and a safe
  page state; one corrupt result never crashes the registry.
- Before rendering any fetcher-produced Markdown, suppress the entire result if
  it contains a prohibited path/internal-URL/port/profile/command/log/response-
  body/credential pattern; show only `QR-SCHEDULES-RESULT-001` and fixed recovery
  copy.
- Keep result fetcher selection/order and schedule cards.
- Retain only the structured human-readable reflection summary, after suppressing
  any field containing a prohibited diagnostic pattern. Remove raw JSON,
  full-source Markdown, and raw-source download controls.

### Institution Portfolio

- Map catalog source/content state through shared components.
- Freshness remains `unknown`; the catalog has no timestamp or stale rule.
- Preserve manual CIK input and provider call behavior for every catalog state.
- Preserve quick-pick labels/CIK mapping, empty catalog behavior, holdings,
  filing-lag warning, and downstream EDGAR fail-soft behavior.

## Acceptance Criteria

### AC-001 — Safe chip rendering

Given labels containing `<script>`, `<img onerror>`, double quotes, single
quotes, and ampersands, when `chip()` renders them, then every label appears only
as escaped text. Given CSS-breaking or unknown color input, the returned style
contains only the fixed muted token and contains none of the supplied value.

### AC-002 — Complete unsafe-site classification

Given the 31 UX-0 unsafe site IDs, the UX-1A classification artifact contains
each exactly once as one of:

- `static_retained`
- `shared_dynamic_escaped`
- `removed_ux1a`
- `deferred_ux4`

No current unsafe site is new/unclassified. Deferred sites remain explicitly
reported and are not described as fixed.

### AC-003 — Diagnostic sentinel exclusion

Given an exception/payload sentinel containing an absolute POSIX and Windows
path, loopback/private URL, port, profile, command, log tail, bearer/token/secret,
and response body, after every target error path:

- none of the sentinel appears in rendered elements;
- none appears in the target session-state projection;
- none appears in newly saved chat JSON or candidate-control history JSONL;
- none appears in captured logs;
- only the stable event code and exception class may appear in internal logs.

### AC-004 — Legacy chat safety without migration

Given a schema-v1 chat containing the exact old generated assistant failure,
`load_chat()` returns the stable safe assistant message. The file hash and mtime
remain unchanged. A user message and a normal assistant message containing the
same words in another shape remain unchanged. The same projection is proved for
an exact legacy failure pre-seeded in live session state and passed through both
`_init_state()` and `_load_payload()`.

### AC-005 — State matrix

For the valid source × content × freshness × operation matrix, pure tests prove
the output contains every applicable dimension and correct severity. Invalid
enum/source/reason/event/recovery values fail closed. Authoritative unavailable,
fallback, partial, empty, stale, and unknown can never be hidden by another
dimension. Arbitrary/path/URL strings supplied as `as_of` are rejected rather
than rendered.

### AC-006 — Fail-soft target artifacts

For missing, half-written JSON, malformed JSON, wrong root, and mocked unreadable
reads, each target AppTest completes without `st.exception`. CSV ledger and
report-directory failures are also safe. Existing `_shared.load_json()` behavior
remains immediate-recovery compatible after cache clear/rerun.

### AC-007 — Source behavior preservation

- authoritative `available=false` performs zero local fallback reads;
- only existing client/transport/protocol failure reasons use local fallback;
- `response_too_large` retains its existing consumer-specific no-bypass rule;
- manual CIK remains usable in every catalog state;
- provider/API call counts match UX-0 for unchanged render cases;
- candidate identities and order match UX-0 fixtures.

### AC-008 — Accessibility scope

For `Chip`, `StateBanner`, and `SourceMeta` only:

- status has icon/text, not color alone;
- chip normal text contrast is at least 4.5:1 on its composited fill over canvas
  and panel;
- focus token is at least 3:1 against adjacent surfaces;
- native semantic alert/caption structure is present;
- content reflows at 320 CSS px without adding component-level horizontal
  overflow;
- no new keyboard trap or focusable element is introduced.

Because `_shared.chip()` is cross-page, a static caller audit must prove every
existing caller still passes an approved constant/token. The seven UX-0 critical
routes receive the standard three-viewport regression capture in addition to the
five focused UX-1A cases. This is a component-level semantic color correction,
not the global theme change reserved for UX-1B.

This criterion does not claim the existing sidebar or AI Chat modal behavior is
fixed.

### AC-009 — Compatibility and scope

The UX-0 compatibility fields remain exact. `.streamlit/config.toml`, `app.py`,
`ui/_read_api.py`, APIs, provider/business files, requirements, and historical
runtime data remain byte-identical. No unexplained file is present in the diff.

### AC-010 — Browser evidence

Owned Chromium captures pass for these cases at 1440×900, 768×1024, 390×844,
and a focused 320×844 reflow check:

- Today Decision default, including candidate controls;
- AI Chat open;
- AI Updates;
- Schedules;
- Institution Portfolio selected.

The existing seven-page UX-0 route matrix also passes at its standard three
viewports to catch cross-page shared-chip regressions.

The runner records a page case separately from route, performs only stable

## Rollback

Rollback is file-only and requires no data migration. It is executable from the
owned Task 0 backup even though the worktree was already dirty/untracked:

1. Verify the owned backup root and every member against
   `quant-radar-ui-v2-ux1a-prechange.json`; abort rollback on any mismatch.
2. Generate a per-file reverse diff from current bytes to the backed-up bytes,
   review its path set, and restore only `existed=true` planned-modified files via
   `apply_patch`. Verify each restored hash equals the manifest.
3. Remove only planned-created paths whose manifest entry is `existed=false`,
   after verifying each path is within the frozen UX-1A list and contains no
   pre-existing user content.
4. Do not touch UX-0 evidence, pre-existing user changes, runtime reports,
   chat/status history, API work, or deployment state.
5. New safe chat/history records remain schema-compatible with the old reader;
   no rollback conversion is needed.
6. Run the pre-UX1A focused suites, full `make test`, protected-hash audit, and
   owned UX-0 browser invocation.

Destructive Git reset/checkout, archive extraction over the worktree, direct
copy-over restoration, and directory-wide deletion are prohibited. The local
backup is retained until explicit acceptance; if it is unavailable or fails a
hash check, rollback stops rather than guessing from Git state.

## Risks and Mitigations

| Risk | Mitigation |
| --- | --- |
| Historical baseline test blocks intentional safety delta | immutable UX-0 evidence plus separate current UX-1A contract |
| Broad legacy redaction corrupts chat content | recognize exact old generated assistant failure only; read-time, no write |
| Candidate UI loses operational usefulness | retain fixed status/stage labels, progress, numeric metrics, controls, auth/resume; remove only raw diagnostics |
| Hidden raw diagnostic survives in code/json/download surface | extend targeted sink inventory and sentinel-test every target surface |
| State banner hides fallback/unavailable/empty dimension | compositional pure matrix and explicit precedence tests |
| Freshness is invented | `unknown` unless an existing timestamp/rule exists; timestamp alone does not imply fresh/stale |
| Chip color hardening changes charts/global palette | map only component chip output; preserve public chart constants and global config |
| Schedule reflection feature regresses unexpectedly | retain allowlisted human summary and test it; deliberately remove only raw-source/debug surfaces |
| Fail-soft catch hides programming defects | catch only target read/render boundaries, log stable event + class, keep tests for valid behavior |
| Browser evidence claims shell fixed | case-specific component metrics; known sidebar problem remains documented for UX-2 |
| Dirty worktree causes unrelated rollback | prechange per-file hashes, exact scope audit, patch-only rollback |
